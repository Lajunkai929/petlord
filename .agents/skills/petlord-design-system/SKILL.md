# PetLord 界面开发

先读 [设计规范](../../../docs/design-system.md)，再查看要修改的现有组件。PetLord 是一个本机创作工具，默认浅色、简洁、暖色；同一项目可以绘图、生成和导入，不增加制作模式选择。

## 实现入口

- 应用从 `@petlord/ui` 导入标准控件。它包装 Ant Design 的交互能力，并提供 Radix 对话框的统一边界。不要在应用里直接引入 `antd` 或 `@radix-ui/react-dialog`，也不要用原生 input/select/textarea 手工模拟标准表单。
- 颜色、字体、尺寸和圆角的唯一值源是 [tokens.json](../../../packages/ui/src/tokens.json)。`theme.ts` 读取它；`npm run tokens:ui` 生成 CSS 变量。修改 token 后同步规范、重新生成并检查，不手改生成文件。
- 标准表单用 `FormField` 配 `Input`、`TextArea`、`SelectField`。使用 `Button`、`Checkbox`、`Radio`、`Switch` 的禁用、加载和状态 API。按钮的视觉 `type` 与表单 `htmlType` 分开。
- `SelectField` 外层 `.pl-select-control` 只负责宽度、flex/grid 位置等布局；不添加边框、padding、背景或高度。可见控件由组件库绘制。
- 新建对象和多字段配置使用 `Dialog` + `DialogContent`。创建 Provider、形象、项目等不能在页面上突然展开一大段临时表单。已选对象的直接属性编辑可以留在其检查面板内。
- 文件选择、颜色拾取、媒体范围滑块和隐藏表单桥接保留原生输入。图节点、像素画布、帧缩略图和拖拽锚点是专用编辑表面，不强行改成普通表单按钮；其文字、颜色和容器圆角仍使用共享角色。

## 视觉约束

沿用小狗和 Logo 的暖白、棕色、焦糖色、暖灰暗色。品牌选择态不改成浅绿、蓝紫渐变或荧光色。不要为了“去 AI 味”添加装饰纹理、随机排版、夸大标题、悬浮缩放或多层卡片。

使用规范中命名的字号、控件密度、圆角和间距角色。标准控件默认同高；紧凑规格必须有实际的密集编辑用途，不能给同一行每个控件随意指定尺寸。系统字体保留中文回退，代码内容才用等宽字体。图像、画布、媒体时序和拖拽坐标属于内容数据，不能按 UI token 取整。

应用的已有外观规则放在 `petlord-application` CSS layer，组件库拥有标准控件的绘制；布局规则可控制宽度、网格和位置。新样式不得再次覆盖组件内部输入框或叠加第二套控件皮肤。

## 验证后交付

1. 运行 `npm run check:design`；检查会拒绝 token 漂移、原始控件绕行、任意 UI 字号/圆角/颜色及 Select 外层绘制。
2. 运行涉及的行为测试和类型检查。验证标准表单的标签、必填、错误、禁用、保存中状态和取消行为；不要用只比对类名或文案的测试代替行为验证。
3. 在真实浏览器或安装包中检查浅色、暗色和 1280 × 800 窗口；影响密度时也检查已有字号偏好。用计算样式确认输入、选择器和同行按钮的高度、字体与圆角。
4. 实际操作 Tab/Shift+Tab、Enter、单击和 Escape。选择器展开时首次 Escape 只关闭选项，关闭弹窗后焦点回到触发按钮。验证取消和失败不会悄悄提交。
5. 查看渲染截图后再说明完成。记录实际覆盖的页面和检查范围；控件测试不能证明宠物美术已达到某种艺术质量。

持续开发沿用用户已有授权；这份 Skill 不增加额外审批步骤。
