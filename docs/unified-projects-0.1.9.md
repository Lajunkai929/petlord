# PetLord 0.1.9：统一项目创作与验收

2026-09-10，macOS arm64。项目不再区分「原生像素」和「AI 生成」两种制作模式，任何项目都可以使用全部创作工具。

## 现在如何使用

- 每个项目固定提供「状态与动作」「绘图」「预览」「发布」。绘制、生成和上传都是为同一个状态图添加素材，切换视图不会转换项目类型。
- 新建项目只需项目名和宠物名；可选复用已有角色，也可以选择「新宠物」后直接开始绘图。
- 侧栏的「配置参考图」通过独立对话框支持上传图片、复用角色、使用当前已确认状态图。在绘图开始的项目中添加参考后，也能直接生成图片。
- 复用角色时跟随其当前参考；项目独立参考会保留自己的素材。更换参考来源不会删除图中使用的旧图片、原生帧或动画。
- 未保存的画布和动画草稿会随工具切换保留，并阻止预览和发布。可以保存，也可以明确放弃草稿。新增状态使用命名对话框。
- 已安装作品仍可直接编辑，保存后在「发布」选择「更新本机宠物」，无需自己导出再导入。

旧源文件的 `productionRoute` 字段继续兼容读取，但不控制工具可用性。原生像素属性和动画时长属于具体素材；普通图片、生成图片、视频与原生动画可以共存。

## 回归修复

参考图合并保留历史素材，处理同 ID 不同图片的碰撞，并复用相同图片的稳定映射。已有共享角色的参考图优先于过时的项目快照，防止重新打开项目时复活旧参考。

参考配置先成功持久化再应用到编辑器。保存期间的并发编辑按照原项目 ID 继续写入，即使已经切换项目也不会遗漏；后续写入失败会保留本地修改，在全局错误条提供「重试保存」。失败重试只发送一次请求，不自动循环。

首次加载等待实际项目从工作区载入后再校验选中状态和更新链接，修复打开绘图链接时被默认状态覆盖的问题。还调整了模板名称展示、绘图草稿提示的无障碍名称，以及原生控件与 Ant Design 按钮的样式优先级。

## 验证

`npm run check` 通过 **108 个文件、484 项测试**，三个应用类型检查及全部工作区构建通过。最后的按钮颜色调整另经桌面构建和最终安装包实测验证。后端、参考素材合并、界面、保存事务及首次加载链接均完成独立范围复核。

最终 0.1.9 安装包的五组实际流程全部通过：

| 流程 | 验证结果 |
| --- | --- |
| 统一创作 | 无角色关联的新项目 → 载入 20 帧彩票样例 → 绑定状态 → 当前状态参考 + 上传参考 → 同一项目生成并采用另一状态 → 重新打开。原生素材完整保留，未写入制作模式。 |
| 绘图与本机更新 | 画布及时间线草稿跨视图保留；放弃恢复原值并解锁发布；保存刷新绑定帧；更新保持安装 key，桌面立即出现指定的新像素颜色。 |
| 导入与 Codex | 订阅导入、相同文件保留两份、删除项目后恢复；隔离配置中一键接入 Codex，实际 MCP 读取、修改一像素、返回反馈并在重启后保留。 |
| Provider | 厂商预设、自定义模型和费用、取消不写入、密钥脱敏与保留、连接测试、编辑焦点恢复、启停及删除；角色和风格对话框。 |
| 注视动画 | 隔离配置中的视频素材下连续移动指针，37 次 seek 完成，进行中重复写入为 0；本轮最长 seek 57 ms，退出回到静态图。 |

五组流程均无 renderer page error。人工查看了浅色和暗色截图，包含 1280 × 800 的统一创作与绘图界面；检查了新增状态及保存画布按钮的实际文字颜色。

生成服务使用本地模拟响应，但走实际请求、抠图与素材入库；未使用真实厂商密钥付费生成。Codex 接入测试使用隔离配置，未修改真实 Codex 设置。彩票美术仍是原创试稿，功能验证不等于已经达到《星露谷物语》的成品美术水准。
