# Lottery full pixel companion

The user asks to extend the existing editable native Lottery project, with all daily actions, pointer gaze, side-facing collar pickup, optional physical desktop waste files, easy Codex notifications and a working/digging loop with visible activity titles. Existing design delegation remains in force.

## Artwork and interaction

Edit `project-lottery-native-frames-v1` in place after backing it up. Preserve original frames and media; add authored native frame/layer data and exact timed transitions for standing, sitting, resting, sleeping, stretching, belly-up, running, squatting/pooping, leg-lift peeing, side collar pickup, digging and attention. Include returns to a reachable hub, idle microloops, and an endless working loop controlled by Agent lifecycle, not a fixed long video. Existing semantic actions and graph remain editable. Native gaze uses eight authored directions, no video downsampling. Drag anchor coincides with the side collar and release returns safely.

Provide direct action access from desktop settings. Running should move the actual pet window within a monitor's work area, stopping during dragging, manual interruption or another action. Non-running states stay where placed.

## Real desktop waste

A `desktopWasteEnabled` boolean defaults false. Poop/pee actions always animate; when enabled a completed corresponding action creates one uniquely named plain-text file in the user's actual Desktop directory, with a matching custom icon and the pet's screen position. Never overwrite existing files or use project text as a path. Track only owned files for status/cleanup, trash only owned generated files. Prevent duplicate files from frame updates, loop iterations and interrupted actions. Finder positioning is best effort: respect OS permission denial and automatic icon arrangement, keep the file and report a precise positioning limitation. Tests use isolated Desktop directories and injected platform adapters.

## Codex activity

Direction is Codex → pet. Use documented lifecycle hooks for start, tool activity, permission needed, completion and interruption; maintain existing legacy notification commands. Setup is reachable from the Agent settings page with connection state, install/repair and test actions. Idempotent scoped edits and backups preserve unrelated Codex configuration. Do not silently write hook trust or bypass a host's trust review. UI must distinguish written configuration from observed live events.

Only display public/visible activity headings, short user-visible progress messages or named tool actions. Never present private reasoning text as a pet transcript. Current hook transcript format is not a stable contract; optional heading extraction is bounded, defensive, and falls back to an explicit activity label. Working loops digging continuously; attention/completion interrupts it, with multiple sessions tracked independently. Do not auto-open another agent session as a result of receiving an event.

## Delivery and verification

Keep the warm shared design system; pure artwork rows are content. No paid generation. Root owns shared desktop wiring and actual data import/upgrade. Candidate package output is separate from the running application. Verify artwork visually, all action reachability/endpoints, native gaze, collar pickup, running bounds, no files when disabled, one file per completed waste action when enabled, notification state transitions, configuration preservation, screenshots and packaged flows. Preserve the six unrelated projects, all identities/styles/media/packages and user settings. Activate the completed Lottery companion as the requested project for desktop use, retaining the former active pet as a switchable installed package.
